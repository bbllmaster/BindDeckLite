    宏与动作帮助

    宏怎么用

    按键的「上位机动作」选 宏，文本框里一行写一步，按顺序执行；改完点右上角「应用配置」下发。宏只在主机侧执行，设备本身仍会照常发送上面的 HID 键（除非该键的 HID 键设为「不发键」）。

    写法作用
    key:Tab发送一个按键或组合键；修饰键用 + 连接，如 key:ctrl+alt+t
    text:hello逐字符模拟输入文本，默认每个字符间隔 20 毫秒
    text!80:pass123同上，但把逐字符间隔改为 80 毫秒（text! 后接毫秒数）；字符丢失时调大
    paste:mypassword把文本放进剪贴板并发送 Ctrl+V（macOS 为 Cmd+V）：中文、特殊符号、密码框等 text: 输不进去的场景优先用它
    wait:500等待 500 毫秒（单位毫秒）
    browser:chrome指定后续 url: 用哪个浏览器打开：chrome / firefox / edge / safari / default（不区分大小写）；浏览器未安装时自动回退默认浏览器
    url:https://example.com打开网址：上面有 browser: 用指定浏览器，否则用默认浏览器；打开后会等待浏览器窗口到前台（Windows 最多 3 秒，macOS/Linux 不等待）再执行下一步
    app:C:\path\app.exe --arg启动桌面应用程序（可执行文件路径，可带参数；含空格的路径或参数用引号包裹，引号可写在参数任意位置，如 --title="My App"）；支持 PATH 程序名（如 app:notepad）与环境变量写法（如 app:%LOCALAPPDATA%\App\app.exe）；Windows 启动后会等待应用窗口到前台（最多 3 秒）再执行下一步，macOS/Linux 不等待，后续 text: / key: / paste: 直接打进去
    无前缀行按 key: 处理，例如单独一行 enter

    日志只记录宏的步骤类型，不记录 text: / paste: 的正文。

    完整示例：用 Chrome 打开页面并登录

    browser:chrome
url:https://example.com/login
wait:1500
key:tab
paste:my-user
key:tab
paste:my-password
key:enter

    browser: 只影响它后面的 url: 步骤，可以写在宏的任意位置；不写就用系统默认浏览器。先等页面加载完再发键，否则按键会落到地址栏或别的窗口。

    完整示例：启动桌面应用并自动输入

    app:"C:\Program Files\MyApp\myapp.exe" --new-session
text:hello world
key:enter

    app: 启动桌面应用后会自动等待窗口获得焦点（Windows 最多 3 秒，macOS/Linux 不等待），再执行后面的 text: / key: / paste:。应用启动较慢时，可用 wait: 手动兜底；可执行文件不存在时，日志会写「app: 未找到可执行文件」并跳过本步，宏继续执行后续步骤。

    参数里的引号可以写在任意位置（app:C:\app.exe --title="My App" 是一个参数 --title=My App），单引号也可以（app:'/usr/bin/foo'）。引号没配对时不会启动任何程序，日志会写「app: 命令行引号不配对」并跳过本步。

    密码框输入无效怎么办

    密码框（以及登录页的邮箱框）是最容易「发得出按键、打不进字」的地方。宏本身不会失败，所以先判断属于下面哪一种情况，再换写法。

    原因典型表现处理办法
    逐字符速度太快 只进去几个字符、顺序错乱，日志显示动作成功 改用 text!80:密码 放慢速度，或直接用 paste:密码
    焦点不在输入框 字打进了地址栏、搜索框或别的窗口 先 wait:1500 等页面加载，再用 key:tab 逐个聚焦；url: 后会自动等浏览器窗口到前台（最多 3 秒）
    输入法 / 键盘布局 中文、emoji、@ # ¥ 之类的符号变成别的字符或丢失 改用 paste:（剪贴板不经过键盘布局）。text: 前先切到英文输入法
    目标程序以管理员权限运行 整个宏对别的程序有效，只对这个程序完全没反应 Windows UIPI 会丢弃低权限进程的合成输入，代码层面绕不过：以管理员身份运行上位机（右键 BindDeckLite.exe → 以管理员身份运行）
    程序主动拦截合成按键 按键、text: 都没反应，但手工输入正常 程序在检测 LLKHF_INJECTED 标记。先试 paste:（它只发一次 Ctrl+V，很多程序放行）；仍不行就是硬限制
    macOS 安全键盘输入 只在密码框里无效，普通输入框正常 「安全键盘输入」会屏蔽合成按键。用 paste:，或临时在输入法菜单里关闭安全键盘输入
    浏览器密码框未渲染完 前几次按键丢失，之后才正常 把 wait: 调到 2000 以上；必要时重复 key:tab

    推荐写法：先 wait:，再 key:tab 聚焦，账号和密码都用 paste:。

    browser:chrome
url:https://example.com/login
wait:2000
key:tab
paste:my-user
key:tab
paste:my-password
key:enter
    • 管理员程序：只要目标程序是「以管理员身份运行」的（任务管理器、部分网银/游戏客户端），上位机也必须以管理员身份运行，否则任何按键方案都无效。
    • 无法绕过的场景：银行安全控件、远程桌面/虚拟机里对合成输入的过滤、带反作弊或主动防御的客户端、UAC 提权弹窗本身。这些场景请改用设备直接发 HID 键，或手动输入。
    • 剪贴板：paste: 会先把原剪贴板里的文本保存下来，粘贴后约 0.4 秒再恢复（只恢复文本，图片等其它内容无法恢复）。这段时间内密码会短暂留在剪贴板里；paste: 不可用时日志会写「剪贴板不可用」，并自动回退成逐字符输入，宏不会中断。
    • Linux / macOS：macOS 用系统自带的 pbcopy；Linux 优先 xclip / xsel（X11）或 wl-copy（Wayland），都没装时回退 tkinter，此时需要图形界面（DISPLAY）。

    常见错误排查

    • 报错 key:xxx is not mapped to any known key：键名不在上面的对照表里。核对拼写（对照表已不区分大小写），组合键用 + 连接。
    • 按了没反应，但卡片在呼吸：这条动作还在执行（卡片边框变亮、「测试动作」变成红色的「停止」），期间重复按下会被忽略，日志里只有一条「动作跳过」。宏结束时会自动恢复；执行期间可点卡片上的「停止」，会在当前步骤结束后退出；已经发出的按键不会撤回。
    • 宏完全没反应：宏需要 keyboard 库（pip install keyboard，Windows 打包版已内置）；确认「设备 → 上位机与系统 → 上位机动作」已开启，动作类型选的是「宏」且点过「应用配置」。
    • 组合键不生效：用 + 连接，key:ctrl+shift+t；不要写成 key:ctrl shift t 或 key:ctrl+alt t。
    • 输入跑到了别的位置：页面还没加载完，把 wait: 调大（如 wait:2000）。
    • 目标程序收不到按键：目标程序以管理员身份运行时，上位机也要以管理员身份运行。
    • Linux / macOS 下按键无效：keyboard 需要 root 权限（sudo python app.py）；不便提权时改用「执行命令」。
    • 网址没打开：url: 后面必须带 http:// 或 https://。
    • 指定的浏览器没生效：browser: 只认 chrome / firefox / edge / safari / default；未安装或名字不认识时日志里会记录原因，并按默认浏览器打开，宏继续执行。
    • text: 输出了奇怪字符：受当前输入法影响，执行前先切到英文输入法；中文或符号改用 paste:。
    • paste: 没反应或只粘贴了旧内容：看日志有没有「剪贴板不可用，paste 步骤跳过」；Linux 需安装 xclip（X11）或 wl-copy（Wayland），或用图形界面下的 tkinter 回退。密码框里仍无效时按上面「密码框输入无效怎么办」逐条排查。
    • app: 启动后字打到了别的窗口：桌面应用启动比浏览器慢，app: 后的 3 秒内（Windows）可能还没抢到焦点。把后面的 text: / key: 前面加一行 wait:1000 手动兜底；仍无效则目标程序可能在后台打开或被 UAC 拦截。macOS/Linux 下 app: 不做自动等待，建议一律加 wait:。
    • app: 报「未找到可执行文件」：路径写错了，或 exe 不在指定位置。含空格的路径用引号包裹，如 app:"C:\Program Files\App\app.exe"；只写程序名（如 app:notepad）时确保它在系统 PATH 里；环境变量写法如 app:%LOCALAPPDATA%\App\app.exe。
    • app: 报「命令行引号不配对」：命令里的引号没成对（多了一个 " 或 '）。此时不会启动任何程序，本步跳过、后续步骤照常执行。检查路径或参数里的引号数量，例如 app:"C:\Program Files\App\app.exe" --title="My App"。
